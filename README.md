# NutriLens — личный дневник питания

> Проект целиком создан **Claude** (Anthropic) в Claude Code по PRD и техспецификации NutriLens.

**Открыть дневник:** https://alexlojkov-code.github.io/nutrilens-created-by-claude/ · **Варианты логотипа:** https://alexlojkov-code.github.io/nutrilens-created-by-claude/logos.html

**Сайт с аккаунтами:** https://nutrilens-orcin-seven.vercel.app

Дневник работает в двух режимах:
- **без аккаунта** — всё хранится только в браузере (`localStorage` и IndexedDB);
- **с аккаунтом** — регистрация и вход по email и паролю, дневник синхронизируется между устройствами. Ключ ИИ и фото на сервер не отправляются.

## Как устроено

- **Vercel** — раздаёт сайт и запускает функции из папки `api/` (Node.js 22, регион `cle1`).
- **Neon** — база Postgres: таблицы `users`, `sessions`, `user_data` (дневник целиком в `jsonb` с номером версии).
- Пароли — `scrypt` со случайной солью. Сессия — случайный токен в cookie `HttpOnly; Secure; SameSite=Lax`, в базе хранится только его SHA-256.
- Изменяющие запросы принимаются только со своего сайта (заголовок `x-nl` + проверка `Origin`).
- После 5 неверных паролей вход в аккаунт блокируется на 15 минут.
- Синхронизация: правки отправляются через ~1 с; если дневник уже изменён на другом устройстве (ответ 409), записи объединяются и отправляются снова.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/auth/register` | регистрация и вход |
| POST | `/api/auth/login` | вход |
| POST | `/api/auth/logout` | выход |
| GET | `/api/auth/me` | кто вошёл |
| POST | `/api/auth/password` | смена пароля (остальные устройства выходят) |
| GET / PUT | `/api/data` | загрузить / сохранить дневник |
| DELETE | `/api/account` | удалить аккаунт и все данные |

## Запуск и публикация

Нужны Node.js 22, `vercel` и `neonctl` (`npm i -g vercel neonctl`), вход: `vercel login`, `neonctl auth`.

```bash
npm install
# таблицы в базе (безопасно запускать повторно)
DATABASE_URL="$(neonctl connection-string --project-id young-bar-56544923)" npm run migrate
# локально: сайт + API на http://localhost:3000
DATABASE_URL="$(neonctl connection-string --project-id young-bar-56544923)" node scripts/dev.mjs
# опубликовать
vercel deploy --prod
```

Без сервера (например, `python3 -m http.server`) сайт тоже работает — просто без аккаунтов.

## ИИ

Настройки → ИИ → API-ключ Anthropic. Запросы идут из браузера напрямую в Claude API. По умолчанию модель Claude Opus 5.5, в настройках можно выбрать Sonnet 5.5 или Haiku 5.5. Для Opus и Sonnet включён серверный fallback на случай отказа модели. Ключ хранится только в браузере и не синхронизируется. Без ключа текст разбирается встроенной базой (~300 продуктов и блюд 38 кухонь мира), а фото и ассистент недоступны.

Модель только разбирает ввод (что и сколько, уверенность, уточняющие вопросы). Нутриенты берутся из базы и считаются кодом: `per_100g × grams / 100`. Если продукта в базе нет, используется оценка ИИ с пометкой «Оценка ИИ».

## Файлы

- `js/foods.js` — база продуктов (USDA и таблицы химсостава, на 100 г)
- `js/profiles.js` — типовые профили блюд и напитков для подбора состава позиций каталога
- `js/dishes.js` — национальные блюда по типовым рецептурам, с привязкой к кухне
- `js/core.js` — хранилище, расчёт нормы (Миффлин — Сан-Жеор), разбор текста, фото, экспорт
- `js/cloud.js` — аккаунт и синхронизация дневника с сервером
- `api/` — серверные функции Vercel, `api/_lib/server.js` — база, пароли, сессии
- `scripts/migrate.mjs` — создание таблиц, `scripts/dev.mjs` — локальный сервер разработки
- `js/ai.js` — запросы к Claude: распознавание со структурированным JSON, валидация и повтор, чат со стримингом
- `js/app.js` — экраны, роутер, анимации
- `js/i18n.js` — русский и английский

## Каталог блюд и напитков

2244 позиции: 33 кухни мира, перекусы и соусы, напитки (206 алкогольных — помечены 18+ и скрыты, если в профиле возраст младше 18). Раздел «Каталог» в меню: плитки кухонь и категорий напитков, поиск по всему каталогу и по базе продуктов.

В исходном каталоге только названия. Для каждой позиции составлен собственный состав по типовому рецепту (оценка ИИ, `data/food_catalog/nutrition.json`):
КБЖУ, клетчатка, сахар, насыщенные жиры, натрий, холестерин и спирт на 100 г (напитки — на 100 мл), типичная порция, английское название,
аллергены (14 основных групп) и пометки «вегетарианское / веганское / без свинины и алкоголя». В интерфейсе такие значения подписаны
«Типовой рецепт · оценка ИИ», при подключённом ИИ их можно уточнить кнопкой «Уточнить с ИИ». Если для позиции нет состава,
он подбирается по похожему блюду из базы (`js/foods.js`, `js/dishes.js`, `js/profiles.js`) или по типовому составу категории.

- `data/food_catalog/` — исходные файлы каталога (`catalog.json`, `CATALOG.md`, `catalog_source.txt`, README) и состав позиций
- `data/food_catalog/nutrition_parts/*.txt` — состав по частям (формат описан в `scripts/import_nutrition.py`)
- `scripts/import_nutrition.py` — проверяет части (калории против БЖУ, диапазоны, порции, пометки) и собирает `nutrition.json`
- `scripts/enrich_catalog.mjs` — альтернатива: то же самое через Claude API пакетным запросом (Message Batches, нужен ключ Anthropic)
- `scripts/build_catalog.py` — собирает компактный `js/catalog-data.js` (284 КБ; грузится только при открытии каталога или поиска)
- `js/catalog.js` — загрузка, состав, поиск по русским и английским названиям

```bash
python3 scripts/import_nutrition.py   # после правки частей состава
python3 scripts/build_catalog.py      # после правки catalog.json или nutrition.json
```
